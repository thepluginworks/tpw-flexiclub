# System Pages

## Overview
System Pages is a registry for front‑end WordPress Pages required by TPW (e.g., My Profile, TPW Control). It ensures pages exist and provides helper lookups.

Canonical contract: [../architecture/system-pages/tpw-core-system-page-protection-contract.md](../architecture/system-pages/tpw-core-system-page-protection-contract.md)

For known private FlexiClub screens, Core also marks the created pages so logged-out fallback page menus such as `wp_page_menu()` / `wp_list_pages()` and block-theme navigation page lists generated by the `core/page-list` block do not expose them automatically. This affects menu listing only; the shortcode or router for each page must still enforce access at runtime.

That private set includes the default Noticeboard route as well as the other member/admin-style FlexiClub pages described in the canonical contract.

## Key Screens / Shortcodes
- Typical pages:
  - My Profile — [tpw_member_profile]
  - TPW Control — [tpw-control]

## Hooks
- tpw/system_pages/defaults (filter) — Modify default registry rows.
- tpw_system_page_url (filter) — Override URL for a registered slug.

## Extending
- Register your page and ensure it exists:
  - TPW_Core_System_Pages::register_page( 'slug', [ 'title' => 'Title', 'shortcode' => '[shortcode]', 'plugin' => 'my-addon', 'required' => 1 ] );
  - TPW_Core_System_Pages::ensure_page( 'slug' );

## Logged-out Fallback Menus
- Core excludes known private FlexiClub System Pages from logged-out automatic page menus.
- This also covers block-theme navigation fallbacks that render a `core/page-list` block from published pages.
- Core does not rewrite arbitrary explicit site menus; only the Core-managed FlexiClub Members Menu is seeded or repaired directly by Core.
- This does not remove or unpublish the pages.
- Access control remains the responsibility of the page shortcode, router, or module permission checks.
